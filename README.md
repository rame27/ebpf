# eBPF Security Suite

High-performance Linux security visibility, detection, and prevention tools
built with **libbpf + C** (CO-RE, BTF-portable). All tools emit structured
**JSON to stdout** for easy ingestion into SIEMs, log aggregators, or
command-line processing with `jq`.

---

## Features

| Feature | Binary | BPF Program | Hook type | What it detects |
|---|---|---|---|---|
| Network Traffic Monitor | `net_traffic` | `net_traffic.bpf.o` | TC ingress/egress | Per-packet IP/port/proto/direction |
| Process Execution Tracer | `proc_exec` | `proc_exec.bpf.o` | tracepoint execve | Every exec with args & parent PID |
| File Integrity Monitor | `file_integrity` | `file_integrity.bpf.o` | tp + kprobe vfs | open/write/unlink/rename/chmod on watched paths |
| Syscall Anomaly Detector | `syscall_anomaly` | `syscall_anomaly.bpf.o` | raw_tracepoint sys_enter | Burst/anomaly scoring per-pid/syscall |
| DNS Query Monitor | `dns_monitor` | `dns_monitor.bpf.o` | kprobe udp_sendmsg | DNS QNAME + QTYPE per process |
| Privilege Escalation Detector | `priv_esc` | `priv_esc.bpf.o` | kprobe commit_creds + tp | UID/GID/capability escalation |
| TCP Connection Tracker | `tcp_tracker` | `tcp_tracker.bpf.o` | kprobe tcp_connect/close | Connect, accept, close, retransmit + duration |
| Threat Detector | `threat_detect` | `threat_detect.bpf.o` | kprobe + tracepoint | Suspicious activity detection |
| Zero Trust Enforcer | `zero_trust` | `zero_trust.bpf.o` | kprobe + tracepoint | Policy enforcement |
| Infrastructure Health | `infra_health` | `infra_health.bpf.o` | kprobe + tracepoint | System health metrics |

## Prerequisites

### Kernel requirements
- Linux **5.8+** (ring buffer, CO-RE)
- Kernel compiled with `CONFIG_DEBUG_INFO_BTF=y` (most distros: ✓)
- `CONFIG_BPF_SYSCALL=y`
- `CONFIG_KPROBE_EVENTS=y`
- `CONFIG_TRACEPOINTS=y`

Check BTF support:
```bash
ls /sys/kernel/btf/vmlinux   # must exist
```

### Build dependencies

**Ubuntu / Debian:**
```bash
sudo apt-get install -y \
    clang llvm libelf-dev zlib1g-dev \
    libbpf-dev linux-headers-$(uname -r) \
    bpftool gcc make
```

**Fedora / RHEL:**
```bash
sudo dnf install -y \
    clang llvm elfutils-libelf-devel zlib-devel \
    libbpf-devel kernel-headers bpftool gcc make
```

**Arch Linux:**
```bash
sudo pacman -S clang llvm libelf zlib libbpf linux-headers bpftool base-devel
```

### Unprivileged User Setup

By default, loading BPF programs requires root privileges. To run eBPF tools as a non-root user, you need to grant Linux capabilities.

**Check current restrictions:**
```bash
cat /proc/sys/kernel/unprivileged_bpf_disabled
# 0 = enabled for unprivileged users
# 1 = disabled for unprivileged users  
# 2 = permanently disabled (requires capability grant)
```

**Required capabilities:**
- `CAP_BPF` - Load BPF programs, create maps, use BPF syscall
- `CAP_PERFMON` - Use perf events, kprobes, tracepoints

**Option 1: Grant capabilities to user (kernel 5.11+):**
```bash
# Grant CAP_BPF and CAP_PERFMON to bash (allows running BPF tools)
sudo setcap cap_bpf,cap_perfmon+ep $(which bash)

# Or create a BPF group and add user:
sudo groupadd -f bpf
sudo usermod -aG bpf $USER
# Then add to /etc/security/limits.conf:
@bpf - memlock unlimited
```

**Option 2: Disable kernel restriction (if value is 0 or 1):**
```bash
sudo sysctl -w kernel.unprivileged_bpf_disabled=0
# Make permanent:
echo "kernel.unprivileged_bpf_disabled=0" | sudo tee /etc/sysctl.d/99-bpf.conf
```

**Option 3: Run with sudo (simplest):**
```bash
sudo ./bin/net_traffic eth0
sudo ./bin/proc_exec | jq .
```

**Verify capabilities:**
```bash
# Check if user can load BPF:
cat /proc/self/status | grep Cap
# Should show cap_bpf and cap_perfmon in effective set
```

## Build

### 1. Generate vmlinux.h (one-time per kernel version)

```bash
# Must be run on the target machine with BTF enabled
bpftool btf dump file /sys/kernel/btf/vmlinux format c > vmlinux.h
```

Or use the Makefile target:
```bash
make vmlinux
```

### 2. Build all features

```bash
make all
```

### 3. Build a single feature

```bash
make net_traffic        # builds bin/net_traffic.bpf.o + bin/net_traffic
make proc_exec
make file_integrity
make syscall_anomaly
make dns_monitor
make priv_esc
make tcp_tracker
make threat_detect
make zero_trust
make infra_health
```

### 4. Clean

```bash
make clean
```

## Running

All binaries require **root** (or `CAP_BPF + CAP_PERFMON`).

### Network Traffic Monitor

```bash
# Monitor interface eth0 (or lo, ens3, etc.)
sudo ./bin/net_traffic eth0

# Monitor loopback
sudo ./bin/net_traffic lo

# Pipe to jq for pretty-print
sudo ./bin/net_traffic eth0 | jq .
```

## Composing All Features

Run all monitors simultaneously and aggregate output:

```bash
IFACE=eth0

sudo ./bin/net_traffic      $IFACE  > /tmp/net.json &
sudo ./bin/proc_exec               > /tmp/exec.json &
sudo ./bin/file_integrity   /etc /var/log > /tmp/file.json &
sudo ./bin/syscall_anomaly         > /tmp/syscall.json &
sudo ./bin/dns_monitor             > /tmp/dns.json &
sudo ./bin/priv_esc                > /tmp/priv.json &
sudo ./bin/tcp_tracker             > /tmp/tcp.json &
sudo ./bin/threat_detect           > /tmp/threat.json &
sudo ./bin/zero_trust             > /tmp/zero_trust.json &
sudo ./bin/infra_health           > /tmp/infra_health.json &

# Tail all JSON streams:
tail -f /tmp/*.json | jq --unbuffered -c '
  {event: .event, pid: .pid, comm: .comm, ts: .ts_ns}
'
```

Pipe to a SIEM (e.g., Elastic/Splunk via Filebeat/Fluentd) by pointing those
tools at the log files, or use a named pipe:

```bash
mkfifo /tmp/ebpf_events
sudo ./bin/proc_exec > /tmp/ebpf_events &
nc -l 9000 < /tmp/ebpf_events   # stream over network
```

## Troubleshooting

| Problem | Fix |
|---|---|
| `vmlinux.h` not found | Run `make vmlinux` first |
| `bpf_object__load: Operation not permitted` | Grant capabilities or use `sudo` (see below) |
| `Failed to attach TC ingress` | Check interface name: `ip link` |
| `BTF not supported` | Upgrade kernel to 5.8+ with `CONFIG_DEBUG_INFO_BTF=y` |
| `libbpf.h not found` | `apt install libbpf-dev` |
| High event volume | Add PID/comm filters in userspace (post-ring-buffer) |
| BPF verifier error | Check kernel version; some features need 5.15+ |
| `reg type unsupported` | Kernel needs `CONFIG_BPF_EVENTS=y`; try sudo |
| `Permission denied` (tracepoint/kprobe) | Need `CAP_PERFMON` capability |

### Solving "Permission denied" for Unprivileged Users

**Step 1: Check kernel restriction status**
```bash
cat /proc/sys/kernel/unprivileged_bpf_disabled
# 0 = unprivileged BPF enabled
# 1 = disabled, can enable with sysctl
# 2 = permanent, requires capabilities
```

**Step 2: Grant capabilities to binary (recommended)**
```bash
# Grant BPF capabilities to each binary:
sudo setcap cap_bpf,cap_perfmon+ep ./bin/net_traffic
sudo setcap cap_bpf,cap_perfmon+ep ./bin/proc_exec
sudo setcap cap_bpf,cap_perfmon+ep ./bin/file_integrity
# ... repeat for all binaries

# Or grant to shell (allows any BPF program):
sudo setcap cap_bpf,cap_perfmon+ep $(which bash)
```

**Step 3: Or disable kernel restriction (if value is 0 or 1)**
```bash
sudo sysctl -w kernel.unprivileged_bpf_disabled=0
# Make permanent:
echo "kernel.unprivileged_bpf_disabled=0" | sudo tee /etc/sysctl.d/99-bpf.conf
```

**Step 4: Fallback - run with sudo**
```bash
sudo ./bin/proc_exec
```

**Verify your setup:**
```bash
# Check capabilities
cat /proc/self/status | grep Cap

# Test loading BPF (should succeed if configured)
bpftool prog load /dev/null /sys/kernel/debug/ - 2>&1
```
